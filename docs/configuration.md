# 服务端配置与检索协议

`backend/.env` 由后端读取，环境变量优先，示例只列出参数名称。不要提交真实配置、把密钥填到浏览器代码，或将服务器开放到公网。仅配置自己确认、信任且有权限的服务；允许来源校验不能判断服务经营者是否可信。

模型适配器发送 `POST {BASE_URL}/chat/completions`，使用 `Authorization: Bearer`。BASE_URL 必须为 HTTPS，不含账号、查询参数或片段。不同服务模型能力和接口兼容性需自行验证，未配置时返回 `NOT_CONFIGURED`。

检索适配器兼容既有 Coze 检索服务的 JSON 契约；也可连接实现相同契约的服务，不是任意 RAG 平台即插即用。启用须同时填写 URL、精确允许 origin 和密钥。凭据只作为 `X-API-Key` 认证头发送，禁止重定向。工具提示要求查询仅包含必要症状与鱼种，不应包含身份、服务端凭据、图片或完整病例历史；这项提示不等于完整的个人信息脱敏器。

请求正文：

```json
{"query":"需要核对的症状与问题","top_k":3}
```

响应示例是虚构的接口数据，不是医学资料：

```json
{
  "sources": [
    {
      "name": "示例观察记录",
      "snippet": "这是虚构的协议示例，不提供病害诊断结论。",
      "documentId": "demo-document",
      "page": 1,
      "chunkIndex": 0,
      "score": 0.7
    }
  ]
}
```

`name`、`snippet`、`documentId` 为必需字段；其余为可选元数据。空 `sources` 表示检索成功但没有结果，认证错误、服务错误和格式错误均独立报告。相关度分数不是疾病概率；资料页码由服务提供，需人工核对。使用知识资料前须取得对应权限，本仓库没有附带文献全文。

开发服务器仅代理 `/api/agents` 到本机后端。前端 `/api/v1` 模式仍是其他业务服务的接口契约，不能据此声称已经实现完整生产后端；默认保留演示模式。
